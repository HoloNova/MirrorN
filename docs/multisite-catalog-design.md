## 已查明的实现边界

- `downloadRules.ts` 只接受北大绑定和一个固定文件；`policy.ts`、`SourceClient`、目录执行器和入库入口都只允许北大。
- 北大目录来自 `/files/` JSON；已直接查看的清华 `/nodejs-release/` 与中科大 `/node/` 是 HTML。中科大官方索引包含 repositories、reverseProxies、downloads，不是一个更新时间字典。
- SQLite 已有整数站点关联，下载及采集范围按站点、软件、目录区分，不需要另造数据库。身份登记、旧目录查询和启用状态仍写死北大，必须一起解除。
- 新首页按软件身份合并来源，下载 API 已绑定站点和筛选；不新增另一套前端数据层、不重做 UI。

## 实施合同

### 1. 审核来源与站点绑定

官方清单／帮助说明确认仓库身份，目录 GET 确认路径和布局，有界包体 GET 确认文件是真实二进制且没有跳到未核实主机。记录检查时点、URL、HTTP 状态、最终主机、读取字节和包头；部分读取不描述为完整下载。无法核实的组合不启用，不以其它软件补足范围。

软件身份与物理目录分离：Node.js 始终是 `nodejs`，清华绑定 `nodejs-release/`，中科大绑定 `node/`。保留既有软件 slug 和资源书签；站点物理仓库的生态必须与绑定的软件生态一致。新增站点绑定引用既有软件规则，只有实际样本显示规则缺口才修改公共软件特性。

manifest 列出本站绑定文件，加载时统一验证：站点来自审核允许表、文件名与站点一致、根路径位于该站审核仓库下、软件生态正确、未知字段／任意执行插件仍拒绝。配置随源码一次加载，不开放在线修改。

### 2. 一条采集链路

后台 SourceClient 限速、有界读取目录；北大 JSON 和普通 HTML 目录转换为相同条目（文件名、目录／文件类型、可确认的大小），再走现有模板、分类、有限未知样本和暂存发布。采用标准 HTML 解析器读取真实目录结构，不把导航、外链、上级目录或错误／验证页面当清单。错误、截断、异常空清单不清掉已有下载。

HTTP 请求／入库 URL 必须位于绑定的准确站点和目录范围，拒绝跨站、认证信息、控制字符和目录越界。包体仅用于接入核查，定时采集器不下载安装器或 ISO。

### 3. 站点隔离与调度

沿用单 worker 和每秒最多一次目录请求，整体资源上限不因新增站点成倍扩大。先处理发布根，再优先处理每个目录排序后的少量最新子目录，随后历史目录；让首批新站下载尽早可查询，不等待北大全部历史版本跑完。

使用通用多站队列隔离原北大 v3 待办；任务仍绑定配置及执行代码摘要，绑定 ID／目录含站点信息，旧摘要不能写入。新队列健康后仅清理已退役的精确旧队列名，不清当前摘要待办。开发抓取库不备份、不复制，不删除现有有效下载或本机测速数据。

每个发布事务只更新一个站点的软件目录，失败保留该目录旧数据；对子目录的撤销不得触及其它站。身份登记按绑定关联软件与站点，不再把所有软件都挂到每个新站。

### 4. 查询与现有前端

兼容资源详情、站点数量、生态数量不再限定北大；新首页仍以统一身份去重。目录分页依旧绑定实际返回内容，文件／版本分页依旧绑定当前站点下载修订。

同一软件各站自己的版本和文件独立返回；切站重新读取该站默认筛选及首批十条文件，不能拼成全局最新版。人工选择与本机偏好不被后台跳站覆盖。只有已核实大陆下载入口的主机加入“节省代理流量”允许列表，海外／未知位置仍排除。

## 有意义的验证

- 真实 HTML 小片段：相对／绝对同站链接、大小单位、转义、重复别名、上级／外链、截断及错误页；北大 JSON 兼容。
- 多站根路径与实际仓库映射；跨站目录／文件不能写入另一站范围；任务和修订隔离。
- 三站相同软件首页只出现一条、来源完整；站点页仅查本站；切站文件／版本不混入另一站。
- 一个站的错误／目录撤销不影响其它站有效数据；新站零下载时不公开空软件。
- 定向类型、lint、数据校验、受影响非 UI 测试、实际发布构建。禁止全量测试和 UI 自动验收；人工 Todo 放入 `docs/acceptance-checklist.md`。
- 发布后核对服务自身日志、实际库内下载数量、公开 API 中新站来源与下载、静态资产挂载。不拿配置存在或本地绿色验证代替已接入。
