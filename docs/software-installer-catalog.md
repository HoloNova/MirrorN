# 软件安装下载目录：当前实现与切换

状态：用户已确认实施，并授权提交、推送和部署。开发阶段抓取数据不备份：新安装目录就绪后切换API，清除旧包库/队列及抓取备份。发布核对进度见PLAN.md。本方案取代 `background-index-implementation-plan.md` 中全量 APT/RPM/PyPI 等范围及最初的三类格式白名单。

## 产品边界

只提供具体软件在 Windows、macOS、Linux 上能直接安装或解压运行的镜像站文件链接。需要前置运行环境的软件由后续教程说明，不承诺每个软件都有三个系统的包。Linux 安装器可以是软件官方的 `.sh`，Windows 可以是 `.exe`，压缩包必须已识别为预编译发行包；不再把源码归档当成新手安装入口。未知软件/命名/用途不猜测、不靠后缀自动收录。

当前只采集北大。身份与采集入口/识别规则需要审核；版本、文件名、大小及直链从后台实时目录元数据取得，不维护实际文件清单，也不迁入旧包/按需目录缓存。只取元数据，不下载安装包、不存原始目录正文。测速不变；页面结构不变，教程占位。

## 一条链路

后台启动强制刷新＋每六小时 BullMQ 调度 → 请求北大 `/files/<软件目录>/` → 识别安装器/预编译包的版本、系统、架构和格式 → 新结果短暂暂存 → 完整校验后事务更新有效下载条目 → API 查询数据库。

源站请求只在 `indexing/source.ts` 及采集任务中执行。API 不联网补数据；前端下载点击和测速仍允许访问源站。目录不是前端产品。旧 `browse/package` 返回 410。

`indexing/software.ts` 仅登记软件身份；`indexing/installers.ts` 维护少量按软件命名规则、动态目录发现和入库。旧协议包采集器/解压库、PyPI 73 万包名待办机制与复制整批文件的快照实现已退出代码路径。

## 已接入的规则与边界

| 目录                                         | 软件条目                      | 收录规则                                                                  | 不收录                                                       |
| -------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `nodejs-release/`                            | Node.js                       | MSI、PKG、三系统预编译归档/Windows ZIP，动态发现历史版本                  | 源码、headers、调试文件、其它系统发行包                      |
| `anaconda/miniconda/`                        | Miniconda                     | Windows EXE、macOS PKG/官方SH安装器、Linux SH                             | conda频道依赖包；任意归档                                    |
| `anaconda/archive/`                          | Anaconda                      | 与Miniconda独立的版本集合，官方三系统安装器                               | 混入Miniconda版本                                            |
| `CRAN/bin/windows/base/`、`CRAN/bin/macosx/` | R                             | R本体EXE/PKG，macOS架构/base目录及历史安装器                              | CRAN依赖库/源码；不能伪造Linux安装包                         |
| `apache/`                                    | 按实际项目分别登记，例如Maven | 目录动态发现；只收项目自身明确带bin/binary的发行归档，版本/二进制目录下钻 | 子项目/插件混入父软件；未标明用途的归档、源码、Maven仓库依赖 |

APK/RPM/DEB/pacman、PyPI、conda频道依赖包、固件、数据集、ISO不属于本轮采集对象。北大40个仓库不再等价于40个下载生态。Apache没有可靠规则的项目不会因注册身份而出现在首页；只有有效安装下载才展示。DMG/AppImage/DEB/RPM等格式并未因“可能友好”自动开放整库收集，接具体软件时再审核用途规则。

目录响应上限4MiB，超额明确失败保旧，不截断后发布；下钻超过16层明确失败，不伪称采完。每次请求限速，目录待办由BullMQ持久化；不手工截掉历史版本。Node目录任务按版本倒序排列。新轮次有独立任务键，避免旧待办阻止新采集；旧任务不能覆盖更晚的有效结果或复活已撤销目录。

## 四类业务实体

新数据库：`MIRRORN_SNAPSHOT_DIR/mirrorn-installers.sqlite`（生产准备目标 `/var/lib/mirrorn/mirrorn-installers.sqlite`）。使用Node 24的 `node:sqlite`，WAL，采集线程写，API独立只读连接。

- `catalog_sites`：短整数ID、站点身份；保留既有测速信息。
- `catalog_software`：短整数ID、软件名字/别名/公开标识、类别、源仓库、教程关联。
- `catalog_versions`：软件ID＋软件版本唯一，镜像站不复制版本身份。
- `catalog_downloads`：版本ID＋站点ID、系统/架构/格式、文件名、直链、大小和可选校验。URL唯一；相同文件名不同URL分别保留。

站点支持哪些生态、某版本有哪些镜像站，都由有效下载关系查询，不维护第二份名单。内部外键使用整数，对外保留 `pku:nodejs-release`、`pku:anaconda` 路由身份；Anaconda单独为 `pku:anaconda-distribution`。

必要辅助表是目录范围、任务日志与暂存行；不是第二套永久文件快照。永久查找索引以短整数关联为主：版本＋站点、站点＋版本、目录范围，加URL去重约束；软件搜索只扫小规模软件名字/别名。源站Packages索引与数据库查询索引是两回事。

同URL采集成功后原位更新；对应完整目录的缺项移除，其它目录保留。失败/中断暂存即时清理（进程中断在下次启动清理），有效数据不动。异常空/数量突降不覆盖；完整父目录可撤销已消失子目录及其后代，旧任务不能复活。任务日志只留7天，定时刷新时清理。

查询分页在同一只读事务内读取，游标绑定查询条件与目录修订号。后台更新后旧游标返回409；前端自动重新读首屏，不为游标保留整套旧文件副本。安装器优先于便携压缩包，版本仍默认镜像站最新，不引入推荐评分。

## 不空窗的发布顺序

1. 现有生产API继续读旧 `mirrorn.sqlite`。运维显式后台准备新库，不搬旧文件记录：

   ```bash
   pnpm exec tsx scripts/prepare-installer-catalog.ts /var/lib/mirrorn/mirrorn-installers.sqlite
   ```

   先准备Node镜像站最新版本、Miniconda/Anaconda、R安装器。历史Node和Apache待办由上线后的后台启动轮补齐，不把预准备视为全站完成。

2. `scripts/deploy-api.sh` 检查四个软件已有有效下载后才更新程序；不创建抓取数据备份。未准备好时拒绝替换现用API，新旧库只在切换期间暂时并存。
3. 新后台队列为 `mirrorn-pku-installers-v2`，绝不复用 `mirrorn-pku-index` 的旧包仓库待办。核对API响应 `catalog: installers-v2`、实际搜索/筛选/直链，再更新公网静态产物供人工验收。
4. 新链路上线且API核对通过后退役旧数据。工具默认只输出计划，加`--apply`删除旧主库/WAL/SHM、旧队列及按命名识别的抓取备份，不创建新的备份：

   ```bash
   node scripts/retire-package-index.mjs /srv/mirrorn/api /var/lib/mirrorn
   # 查看计划后，在获准退役时加 --apply
   ```

   工具验证本机新API已提供安装下载、新库有效，先清除旧队列，再删除旧库/旧目录缓存及`mirrorn*.before-*.sqlite`抓取备份及其WAL/SHM；保留新库、当前队列、测速状态与非抓取数据。不能删容器/数据卷来替代这一步。
