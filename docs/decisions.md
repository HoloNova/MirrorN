## 2026-10-06：整体归档旧系统，以 Git 文档资源站重建

状态：用户确认，旧受控文件已归档；新站实现尚未开始。

原因：目标是贡献者共同维护的资源文档，而不是数据库驱动的镜像／生态后台。继续兼容旧模型会把采集、账户、接口、样式和运行依赖带回新项目。

决定：旧源码、工具链、CI、部署、设计与历史说明进入 `archive/legacy/`。原始文件清单及 SHA256 用于核对完整性。本地数据单独隔离。新站不引用旧包，不自动迁移旧库。复用只允许按需提取，不保留运行时桥接。

放弃方案：渐进替换旧后台、数据库/Git 双向同步、旧生态接口兼容层。代价是旧站不再能在根目录直接启动；这是明确的退役结果，不是回归缺陷。

决定：Astro 静态输出、TypeScript、原生轻交互、语义 CSS、构建生成搜索索引。只为内容和交互增加依赖，不引入数据库、后端服务或框架运行时作为预留。

## 2026-10-06：受限 MDX AST，而不是执行完整 MDX

状态：已被下文「自定义 Markdown 指令」决策取代，保留为设计历史，不再指导实现。

决定：复用 remark-mdx 解析语法，只允许白名单组件和字符串属性；数组、对象和来源放配套 JSON。不支持文档 import/export、表达式或任意 HTML，不执行生成的 JS。

原因：全局组件复用不要求文档成为程序。仅限制组件名却执行 MDX 表达式会使规范失去边界。这个限制属于稳定内容格式，不是另建安全防护产品。

代价：用户最初示例中的 options 表达式需要改为 group 引用。收益：链接修订、校验、主题和组件升级不要求逐篇重写文档。

## 2026-10-06：来源与产物分离，解析先静态化

状态：本轮内容规格选定。

决定：资源持有 artifacts、sources、groups 和 assets；组件引用稳定 ID。下载解析先是构建期纯函数，输出链接／命令，不部署通用 302 服务。

原因：来源网站性质并不等于下载行为；GitHub 发布页和具体资产必须区分。相同版本但字节不同的包不是可以任意替换的镜像。

## P0 确认补充：自定义 Markdown 指令，不使用 MDX 标签作为作者接口

状态：用户已明确确认写作方向，P0 规范已更新；解析器与组件待后续阶段实现。本决策取代上文受限 MDX 标签方案。

决定：资源文档使用 `index.md`；通过 `::download{source="official-file"}`、`::download-select{group="installers"}` 等叶子指令和 `:::notice` 容器指令声明功能。使用 remark-directive 解析 AST，站点统一注册名称、参数与组件映射。文档作者只写 Markdown、参数和数据引用，不写 JSX、组件实现或 import。

原因：用户要的是可复用的自定义 Markdown 语法，而不是每篇 MDX 手写组件标签。共享组件是站点实现细节，语法是贡献者接口；两者分离后，组件视觉或交互升级不会迫使贡献者改写文档。

替代方案：保留 MDX 标签、逐篇定义组件、用正则替换扩展语法。前两者增加作者负担且偏离确认需求，后者难以正确处理代码块与嵌套结构，均不采用。

影响：更新内容规范、架构、贡献示例、P2 与验收条件；产物／来源模型和八项功能不变。尚无新资源或实现，因此只修订未落地的 v1 规格，不创建旧 MDX 兼容层。

## P4 编辑入口：主动提交 PR，不按保存自动新建

状态：用户已确认，P4 已实现 GitHub 编辑链接；不建设自动提 PR 能力。

决定：编辑此页跳转仓库对应文件的编辑器，贡献者在自己的工作分支上完成修改后主动提 PR。同一资源的正文、来源和附件尽量合并为一个 PR，审核期间的修订继续更新这个 PR；不同任务不强行合并成巨型 PR。

对比：每次保存自动新建 PR 会产生半成品或重复请求，并要求静态站额外处理身份、写仓库权限、分支和 PR 生命周期；跳转 Git 平台编辑器复用已有审核流程，不增加站内后台。仍需要贡献者登录 Git 平台并主动完成提交，这是简化站点的明确取舍。

原因：PR 频率主要由变更划分和新建时机决定，不应等同于编辑或保存次数。先复用 Git 协作机制；只有实际贡献成本证明需要时，再讨论复用分支／草稿 PR 的在线编辑器，不在 P4 预建。

## P5：轻量公开索引与原生首页搜索

状态：已实现，待人工验收。

决定：复用公开 Registry 投影为摘要地址静态 JSON，Fuse.js 7.5.0 做字段加权检索，精确名称与精确别名优先；归一化规则、预算与稳定排序集中在 Search 模块。JSON Schema 同时用于构建与浏览器校验，URL 从合法 ID 生成；不搜索全文或发放完整 Registry，不引入数据库、API、拼音猜测或 UI 框架。
