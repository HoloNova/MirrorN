## 2. 关键回归点（最容易碰坏的地方）

**命令生成。** 切换系统、终端、发行版版本、来源之后，第 2 节的命令与配置文件内容必须一起改写，且不能出现跨系统混用（例如 Windows 版式下出现 Linux 的 `sudo` 命令）。apt 选 `24.04` 是 deb822（`/etc/apt/sources.list.d/ubuntu.sources`，`Types:`/`URIs:`/`Suites:`），选 `22.04` 是一行式 `/etc/apt/sources.list`；两种情况 `-security` 都指向官方 `security.ubuntu.com`。

**推荐逻辑。** 最快且同步状态未被阻塞的来源带「推荐」标记并被默认选中；手动点过任一来源后，后续测量不得替换它；同步失败（或暂停）的来源不得被自动推荐，但仍可手动选择。

**同步状态。** `/api` 不可用时显示「同步状态未知」，页面完整可用、控制台无报错；数据可能过期时明确标注；界面显示的同步状态必须与推荐结果一致（不能出现"写着同步失败却仍被推荐"）。

**主题三处一致。** `apps/web/src/lib/theme.ts` 的注册表、`apps/web/src/styles/themes/*.css` 的 `[data-theme=…]` 选择器、`apps/web/index.html` 首屏脚本里的主题白名单必须一一对应。这条现在没有自动测试守着，加主题或改配色后必须人工核对第 1 项。

**测速口径。** 进入生态页才开始测量（首页默认不测）；1500 ms 内没有响应记为「超时」而不是失败；no-cors 的来源要说明「响应完成，内容未验证」，不能读成"仓库正常"。
