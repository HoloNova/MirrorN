# 界面系统：规则、机制与落地清单

本文件说明 MirrorN 新界面系统的设计规则、主题机制，以及把现有应用切换到这套系统的落地清单。
代码实体在 `apps/web/src/styles/`，可交互的设计样张是 `apps/web/design-preview.html`。

---

## 1. 视觉方向与理由

产品的核心动作是「在**你的浏览器里**测出哪个镜像源对你快，然后照着文档改配置」。所以页面上最该被
记住的应该是**测量结果本身**，不是配色，也不是卡片。由此定下方向：

- **工程图纸 + 测量仪表**：冷调纸白底、细线、刻度、等宽数字；中文按中文的排版习惯设置。
- **颜色只承担语义**：结构用墨蓝（`--struct`），状态只有绿 / 琥珀 / 红三色。全站没有装饰性强调色，
  因此界面上每一处彩色都在表达"可点击"或"某个状态"。
- **唯一"花力气"的元素是延迟读数条**：有数据用实心刻度、无数据用 45° 剖面线，刻度长度等于综合得分里
  的延迟分 `1 - 耗时 / 1500`。剖面线是技术制图里"此处无数据"的惯例，既省文字，也不会被误读成某个状态。

以下做法是**刻意避开**的（它们是目前 AI 生成界面的默认套路，不针对具体产品）：

| 避开                                                    | 在这次改造里对应的处理                                           |
| ------------------------------------------------------- | ---------------------------------------------------------------- |
| 近黑底 + 单一霓虹强调色                                 | 原配色是 `#0b0d10` + 青色 `#5eead4`，本次整体替换                |
| 内容切成一张张同款圆角卡片                              | 目录改成账本式列表，面板只用细线与左侧标记                       |
| 小标签全大写 / 等宽小字标签 / 药丸徽标 / 链接尾部加 `→` | 全部去掉；类别标签用小方框，推荐标记用一根刻度 + 文字            |
| 每个区块都做入场动画                                    | 只有回答用户操作的动效：复制反馈、读数条填充、测量中的剖面线漂移 |

## 2. 分层与文件职责

| 文件                       | 层             | 允许放什么                                                     |
| -------------------------- | -------------- | -------------------------------------------------------------- |
| `styles/fonts.css`         | 字体           | `@font-face`；自托管，只取需要的子集                           |
| `styles/tokens.css`        | 原子层         | 字族、字号、行高、间距、圆角、动效、宽度上限。**主题不得覆盖** |
| `styles/themes/survey.css` | 语义层（默认） | 面 / 墨 / 线 / 结构色 / 状态色 / 代码 / 交互反馈变量           |
| `styles/themes/carbon.css` | 语义层         | 同上，只换值                                                   |
| `styles/base.css`          | 基础层         | 元素级默认：字体、行高、焦点环、选中态、减少动效               |
| `styles/doc.css`           | 组件           | 顶栏、页头、粘性参数条、目录栏、章节、清单、提示条、折叠、页脚 |
| `styles/readout.css`       | 组件           | 延迟读数条、同步状态、推荐标记、类别标签                       |
| `styles/command.css`       | 组件           | 命令块、复制按钮与状态、占位符高亮                             |
| `styles/controls.css`      | 组件           | 按钮、镜像选择行、动作行                                       |
| `styles/search.css`        | 组件           | 搜索输入与结果列表                                             |
| `styles/home.css`          | 组件           | 首页标题、搜索、本机测量入口、生态账本                         |
| `styles/index.css`         | 入口           | 汇总 `@import`，顺序：字体 → 原子 → 主题 → 基础 → 组件         |

**组件层只允许引用语义变量。** 组件里出现 `#rrggbb` 或 `rgba(...)` 字面量就意味着它无法跟随主题，
按缺陷处理（原 `styles.css` 里有 99 处颜色字面量，这正是要重做的原因）。

## 3. 主题机制

- **`data-theme` 永远是一个具体主题 id**（`survey` / `carbon`），不写 `system`。「跟随系统」由 JS 用
  `matchMedia('(prefers-color-scheme: dark)')` 解析成具体 id 后再写到 `<html>`。这样 CSS 侧只认识具体
  主题，加主题不需要在 CSS 里写媒体查询分支。
- **选择器互斥，不依赖文件顺序**：默认主题写 `:root:not([data-theme])`，其余写 `:root[data-theme='<id>']`。
  互斥选择器之间没有层叠竞争，import 顺序变化不会改变结果。
- **首屏不闪白**：`index.html` 里放一段极小的内联脚本，在样式生效前读取 `localStorage` 并写好
  `data-theme`。静态部署没有 SSR，这一步不可省。内联脚本与 `lib/theme.ts` 共用同一套解析规则
  （内联脚本不能 import，所以是几行重复代码 + 一处注释说明）。
- **`color-scheme`**：每个主题声明 `light` / `dark`，让滚动条与原生控件跟主题一致。
- **加一个主题的完整动作**：新增 `styles/themes/<id>.css` → 在 `lib/theme.ts` 注册表加一行（id、名称、
  预览色、scheme）→ 把 id 加进 `index.html` 内联脚本的白名单。这三处必须一起改；界面不做自动化测试，
  所以按 `docs/acceptance-checklist.md` 第 1 项人工核对（切换三个选项都生效、刷新不闪白）。

## 4. 硬规则（评审清单）

1. 组件 CSS 不出现颜色字面量，只引用语义变量。
2. 颜色只表达语义：结构色只用于可点击与当前位置，状态只有绿 / 琥珀 / 红。
3. 中文正文 15px / 行高 1.8，行宽按 `--measure`（620px ≈ 40 字）控制——比英文站点惯用的行宽窄。
4. 数字一律等宽并 `tabular-nums`：毫秒、时刻、数量要在同一列里能直接比大小。
5. 读数条：有数据实心、无数据剖面线；长度 = 延迟分，颜色只是这个分数的读法，不得与长度矛盾。
6. 不用卡片墙、药丸徽标、全大写小标签、Emoji、渐变色装饰。
7. 动效只用于回答用户动作或说明"什么变了"；入场动画全站不做。
8. 焦点环只在 `base.css` 里定义一次（`:focus-visible`），组件不另写。
9. 命令块不做深色"终端皮肤"：一页会出现三四个，块块深色会把文档切成重块；深色留给深色主题。

## 5. 字体与体积

- 拉丁与数字：**IBM Plex Sans Variable**（latin 子集 45.7 kB）+ **IBM Plex Mono** 400/500
  （14.7 / 14.9 kB），全部自托管，构建后落在 `/assets/*`（Caddy 已配置一年 immutable 缓存）。
- **不引入中文 Web 字体**：单字重就是数 MB，而本站首页讲的正是响应耗时，为排版下载几 MB 自相矛盾；
  离线/校园网场景也不该依赖第三方字体 CDN。中文走系统栈（PingFang SC / HarmonyOS Sans / Noto Sans
  CJK / 微软雅黑），因此中文字重只用系统普遍存在的 400 / 500 / 600 三档。
- 为何是 Plex：这套内容全是终端命令、地址与毫秒数，Plex 的拉丁字形本身是工程-技术语感，且与等宽的
  Plex Mono 同源，数字与代码并排时基线一致。

对比度（WCAG 2.1，正文要求 ≥ 4.5:1，格式「页面底 / 面板」）：

| 变量       | 测绘图（浅） | 碳黑（深）  |
| ---------- | ------------ | ----------- |
| `--ink`    | 16.1 / 17.6  | 15.4 / 14.5 |
| `--ink-2`  | 7.2 / 7.9    | 8.7 / 8.2   |
| `--ink-3`  | 4.7 / 5.2    | 5.2 / 4.9   |
| `--struct` | 10.7 / 11.7  | 8.3 / 7.8   |
| `--ok`     | 4.9 / 5.4    | 8.1 / 7.6   |
| `--warn`   | 5.1 / 5.6    | 8.2 / 7.7   |
| `--bad`    | 5.7 / 6.3    | 6.4 / 6.0   |

## 6. 设计样张页

`apps/web/design-preview.html` 用真实数据（Node.js / npm 的换源内容）把每个部件摆出来：色板、排版、
读数条与状态、命令块、控件与提示，以及"文档形态"的完整生态页和首页形态。打开方式：

```bash
pnpm dev:web      # 然后访问 http://127.0.0.1:5173/design-preview.html
```

它**不参与线上构建**：Vite 默认只把 `index.html` 作为构建入口，所以这个文件不会进 `dist/`。
页面上所有耗时数字都是示意值，脚本里也不连接任何镜像站。

## 7. 把应用切换到新系统：落地清单

1. **主题基础设施**：新增 `lib/theme.ts`（注册表 + 解析规则）、`composables/useTheme.ts`、
   `components/ThemeSwitcher.vue`；`index.html` 加首屏内联脚本与 `theme-color`（三处 id 与配色必须一致）。
2. **样式入口**：`main.ts` 改为 `import './styles/index.css'`，删除旧的 `styles.css`。
3. **外壳**：`App.vue` 换成 `.shell / .topbar / .shell-main / .footer` 结构，顶栏放品牌、数据模式、主题切换。
4. **首页**：`HomePage.vue` 换成 hero + 搜索 + 本机测量入口 + 账本式生态目录；测量默认不发起，用户点击才测。
5. **生态页改成文档形态**：`EcosystemWizard.vue` 拆成
   `EcosystemDoc.vue`（页头 + 前置条件 + 参数条 + 目录栏 + 全部章节一次渲染）；
   `lib/wizard.ts` 去掉 `step / canProceed / next / previous / goToStep`，保留
   `os / shell / version / mirrorId` 与推荐逻辑，改名为参数状态（`lib/guideParams.ts`）。
   命令生成链路（`@mirrorn/shared/generators`）与数据层不动。
6. **组件**：`CommandBlock.vue` 增加占位符高亮（把 `<包名>` 包成 `.ph`）与 `data-state` 复制反馈；
   `ProbeBadge.vue` 换成读数条；`TroubleshootingList.vue` 换成 `.disclosure`；`SearchBar.vue` 复用新样式。
7. **进度**：每个动作章节一个"我已完成"勾选（`localStorage`），目录栏显示 3 格进度；**不做门禁**，
   任何内容都不再因为未完成而上锁。
8. **测试**：`lib/wizard.test.ts` 按去掉的字段重写为 `lib/guideParams.test.ts`（纯逻辑：系统/终端/版本/来源联动与推荐），界面行为不做自动化测试，验收方式见 `docs/acceptance-checklist.md`（第 5–13 项逐条对应文档形态）。

### 尚未决定的三件事

- **首页"测量我的网络"测哪些镜像**：候选集不该手写死在页面里，具体规则待定（倾向：取数据中同时服务
  多个生态、且声明了探针的来源）。
- **移动端参数条**：三个参数组在 390px 宽下会折成三行，常驻会吃掉约 14% 的视口高度。倾向改成
  "系统 · 终端 · 来源"一行摘要 + `调整` 展开，需要组件里的展开状态。
- **文档内锚点与 URL**：当前是 hash 路由（`docs/decisions.md`），文档内跳转要么接受 hash 里再嵌一层，
  要么改 history 模式并在 `deploy/Caddyfile.mirror` 加 `try_files` 回退。倾向先接受 hash 内嵌。
