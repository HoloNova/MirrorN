# 北大规则草案：主会话接手后的复核与修订

状态：规则审核阶段已完成；全部配置仍为 `draft`，不是生产可加载配置。基线 `main@1e922fb`。没有修改采集程序、业务数据库、Redis、查询接口或线上。原始外部 Agent 工件保留在 `docs/tmp/`，未覆盖其声明。

## 本轮结果

- 主会话串行执行 80 次限额元数据请求，共 562,357 字节（约 549 KiB）；仅北大 `/files/` JSON，每响应最多 1 MiB，不下载任何包体或展开全量包索引。
- 40/40 仓库均有当前根级身份证据；17 个仓库有选定文件叶子证据。根存在不证明里面所有文件已核验，也不证明文件可运行、当前官方版本新鲜或源站下载响应已验证。
- 修订为 26 份软件/平台采集配置候选，关联 15 个现有生态 ID；另外 3 项保留为范围/安装方式待定。26 是规则配置数量，不是生态数，也不是软件数：R 的两个平台配置属于同一软件；Kubernetes 的一个配置只允许四个独立工具身份。
- 验证 121 个真实正样本、93 个真实非候选样本和 25 个独立回归断言，共 239 个文件名断言。它们验证候选文件名与原始字段捕获，不冒充尚未实现的运行时分类器、字段清洗器、平台兼容性、更新/删除闸门测试。
- 未把外部研究的“无安装价值”结论原样采纳：只核实根的仓库保留待评估状态，不删除生态；源码-only、依赖-only 等全仓库结论需要独立证据，不能由一个目录推及全部。

### 字段及去重决策

使用现项目的架构标准值 `x64`，原始 `amd64/x86_64/x64` 标签保留供审计；缺证据时是 `unknown`，不推断 universal。ISO 的系统是目标安装系统，不是制作启动盘的宿主系统。

规则中的 `fieldPolicy` 和 `discovery` 是审核说明，不是可执行 DSL；`filenameCandidates` 只定义在审核上下文中的命名包络。接入前必须用设计中的受控模板/命名解析器实现平台、格式与用途交叉验证、版本来源、渠道、前置条件和三态更新。不能把“正则命中”直接当完整安装资源判定。

版本别名不凭同大小合并。未证明 `latest/current` 指向时保持候选/明确别名记录，不把它说成正式数值版本，不让不识别导致已有效条目消失；数字版本可独立正常采集。不同构建、Python/Scala/Hadoop 变体、介质不得用同软件版本粗暴折叠。

## 接入顺序与剩余覆盖

1. 实现规则加载/交叉校验、受控模板、字段规范化；规则跟程序发布，不开放管理接口或热更新。先把既有 Node/Conda/R 迁入新规则，并用样本保证不回退。
2. 建立生态—软件—站点关系。40 个仓库的已核验身份可被登记，下载是否可用单独表述；不能为了达到显示数量让未核实条目冒充下载。
3. 接入已取证的 TeX、Linux 安装镜像、Apache 六个项目和 Kubernetes 工具；更新成功后才变更对应范围，网络失败/未知项保旧。适用系统/环境未确认的配置仍不激活。
4. 针对剩余入口分批取证：Ubuntu 其它 flavour/ports；CentOS/Stream/Vault；Debian DVD/live/nonfree；Rocky Vault；Apache 长尾；CRAN 历史布局；其它架构。不得把本轮 15 生态候选当成最终范围白名单。
5. OpenWrt、ImmortalWrt、OPNsense 的固件/目标系统建模暂不自动扩产品。它们的生态身份保留；OPNsense 的 DVD 已有证据，不能说没有安装镜像。AOSC 经补证已从待定改为 ISO 配置候选。

所有当前范围内仓库都可以产生“入口待适配/用途待核对”的结果，不需要在少数白名单以外直接停止发现。目录发现有审核根和布局约束，不能为扩大数量而恢复全站包池扫描。

本轮不承诺剩余仓库不存在安装资源，不承诺所有现有候选已是正式最新版本，也不承诺覆盖全部历史版本。下一阶段的生产集成与发布必须单独验证，不能把本研究文件放进运行清单即宣称完成。
