# 人工策划内容管理

## 当前边界

MirrorN 面向初学者，以生态和教程为入口，人工选择要提供的版本及资源。Agent 的调研结果需要维护者审核后录入，不自动批量导入镜像库存。旧采集器和旧文件库保留代码，但默认不运行、不混入新公开搜索。

首页仍只有搜索框；`/#/ecosystems` 展示已发布生态；`/#/ecosystems/<标识>` 展示人工整理的版本、入口、依赖和教程。站点页暂时跳转到生态列表。管理页是 `/#/admin`。

## 本地使用

要求 Node.js 24+、项目锁定的 pnpm。人工管理使用 Node 内置 SQLite，不需要 Redis。

```sh
pnpm install
pnpm admin:setup
pnpm dev
```

`admin:setup` 在终端询问用户名、两次密码（隐藏输入，至少12个字符），没有默认账号。已有账号不会被覆盖；忘记密码时执行 `pnpm admin:setup --reset`。用户名、随机盐与 scrypt 密码摘要存储在人工内容库，密码不放进源码或环境变量。重置账号后已有管理会话失效。

浏览器访问 `http://127.0.0.1:5173/#/admin`。登录会话使用 HttpOnly、SameSite=Strict Cookie，8小时到期；后端重启需要重新登录。写请求还必须通过 CSRF 校验。所有新内容接口使用同源 `/api`，不要单独把管理API配置到另一域名。

根目录 `.env` 在后端启动与维护命令执行时读取；已经设置的进程环境变量优先。默认人工库：`apps/server/.data/mirrorn-curated.sqlite`；`MIRRORN_SNAPSHOT_DIR` 可更改其目录，相对路径以仓库根为基准。旧库 `mirrorn-installers.sqlite` 不导入、不删除。两者没有共享写入或版本清理。

## 整理一个生态

1. 创建生态名称与唯一标识（如 `nodejs`）。标识创建后不修改，用于稳定页面地址。
2. 填写简介、分类和搜索别名。生态自身已可维护版本，无需再建同名组成项。
3. 必要时添加软件、工具或模块组成项，例如单独维护的包管理工具。
4. 添加具体版本，填写支线、发行类型、推荐用途及理由。LTS、最新稳定、课程兼容由维护者判断，不由规则自动推断。“默认推荐”每个组成项最多一个；推荐必须填写理由。
5. 在版本下添加具体资源，区分平台、架构和文件类型，再为**同一资源**填写多条来源。无独立版本的资源可不关联版本。大小、校验值、核查日期不强制填写，不伪造。
6. 添加依赖说明：谁需要它、是否可选、版本条件、适用版本／平台。可关联另一已发布生态，也可只填写文字；不自动解析或安装依赖。
7. 编写Markdown教程，注明适用版本、平台和关联资源，不需要按每个版本复制教程。支持标题、段落、列表、引用、围栏代码、行内代码、加粗和安全链接；不支持直接HTML、表格和图片。
8. 将完成的条目标记为“发布时收录”，未完成条目保持草稿。保存并预览，检查通过后保存并发布。

入口类型决定按钮：文件是“下载文件”、目录是“浏览目录”、仓库／配置入口是“查看仓库／配置入口”。目录不冒充可下载的整个文件夹。

## 草稿、发布与停用

一个生态保存完整编辑稿，并独立保留最近一次发布快照。保存编辑稿**不改变公开页面**。发布时过滤草稿／停用条目和未启用来源，校验名称、推荐理由、文件字段、引用及可用入口，然后用单次SQLite更新原子替换公开快照。

已发布条目引用草稿／停用的组成项、版本或资源会阻止发布，避免隐式泄漏草稿或丢失适用范围。草稿保存也验证标识唯一性和引用关系；不完整的文字内容可留空。

生态至少要有一个可用资源或教程才能发布。只发布组成项、没有资源或教程的空生态不公开。一个资源至少有一条完整、启用的HTTP(S)来源。

版本、资源、教程用条目状态停用；来源可单独取消启用。需要重新发布生态才会更新公开内容。整个生态停用后立即退出新公开列表和搜索，但保留编辑稿及历史发布快照，可编辑后再次发布。移除草稿条目前先解除引用；已收录条目默认用停用而非删除。

编辑使用修订号，另一窗口先保存后，旧窗口不能覆盖它。遇到409请保留需要的修改，重新载入编辑页后合并再保存。未保存离开会提示。

## 下载来源与测速

一个资源的备用来源必须是相同版本、平台、架构和安装形式。不会为了选择更快站点而切换文件。维护者可以关联已审核站点身份，复用原有探针元数据；只有链接主机与站点身份相符时才参与旧测速缓存选择。

本阶段**不新增测速流程**：沿用既有手动来源偏好和仍有效、出口指纹匹配的测速缓存；无缓存／无法校验指纹时按维护顺序选择，页面允许切换。自定义来源仍可下载，不伪称已测出最佳速度。完整自动测速和自动监控留待后续。

## 备份与恢复

人工数据不能像抓取库存一样随时重采。

- 管理列表的“导出全部内容”下载JSON，包含编辑稿、已发布快照和修订信息，不含管理员凭据。用于审阅、归档和以后迁移，本阶段不提供批量导入按钮。
- `pnpm content:backup backups/content-YYYY-MM-DD.sqlite` 使用SQLite `VACUUM INTO` 创建一致性数据库备份，**包括账号摘要**。可在应用运行时执行，包含已提交WAL数据；已有备份文件不会被覆盖。`backups/` 已忽略，不提交仓库。
- 恢复：先停止 `pnpm dev`，另行备份当前人工库，将备份文件放到配置目录的 `mirrorn-curated.sqlite`，确保没有遗留的旧 `-wal`／`-shm` 文件，再启动。只操作人工库，不替换旧采集库。备份包含管理员账号，如需更改执行 `pnpm admin:setup --reset`。

## 接口与实现坐标

新接口成功响应统一为 `{ data: ... }`，失败为 `{ error: "..." }`，使用真实HTTP状态码。登录和管理操作有限速；单次管理内容最多1MiB。

| 接口                                        | 用途                           |
| ------------------------------------------- | ------------------------------ |
| `GET /api/curated/ecosystems?q=`            | 已发布生态列表／搜索           |
| `GET /api/curated/ecosystems/:id`           | 已发布快照                     |
| `POST/GET/DELETE /api/admin/session`        | 登录／会话校验／退出           |
| `GET/POST /api/admin/ecosystems`            | 管理列表／新建草稿             |
| `GET/PUT /api/admin/ecosystems/:id`         | 读取／保存编辑稿（含revision） |
| `GET /api/admin/ecosystems/:id/preview`     | 校验并生成发布预览，必须登录   |
| `PUT /api/admin/ecosystems/:id/publication` | 发布或停用（含revision）       |
| `GET /api/admin/export`                     | 导出人工内容，不导出账号       |

契约：`packages/shared/src/curation.ts`。存储、发布、登录及API：`apps/server/src/curation/`。后台页面：`apps/web/src/pages/Admin*.vue`；表单及公开内容组件：`apps/web/src/components/curation/`。

旧接口和采集文件仍保留，供之后逐项退役，不作为新内容事实来源。显式开启 `MIRRORN_CRAWL_ENABLED=true` 只运行旧库采集，不改变新公开列表。

## 人工验收 Todo

不使用UI单元测试、浏览器自动验收或公网部署。由维护者本地启动后检查：

- [ ] 首次设置账号并登录，错误密码不能登录；退出后不能管理。
- [ ] 新建Node生态、版本、资源与两条来源、依赖和教程；草稿不出现在首页搜索／生态列表。
- [ ] 保存并刷新编辑页，内容仍在；Markdown预览和整页发布预览可用。
- [ ] 缺少推荐理由、完整启用链接或引用未发布条目时，发布显示具体错误。
- [ ] 发布后首页能搜索到生态和别名，详情能切换组成项、版本、平台及来源。
- [ ] 文件／目录／仓库按钮分别正确，不把目录显示成下载安装包。
- [ ] 修改已发布内容仅保存编辑稿，公开内容保持原样；再次发布才更新。
- [ ] 停用某来源后发布、停用生态，公开展示相应更新；重启后数据保留。
- [ ] 两个窗口编辑同一生态，旧修订不能覆盖新修订；未保存离开有提示。
- [ ] 导出JSON不含账号；数据库备份命令成功。窄屏和深色主题下表单可用。
